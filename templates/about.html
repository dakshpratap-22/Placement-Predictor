About Placement Predictor

A college mini-project demonstrating a machine-learning workflow in a Flask web app.

Predictions are estimates, not guarantees of employment. Real placement depends on interviews, company requirements, openings and many factors this model never sees.

Project objective

Help students estimate a placement outcome from their academic profile, check readiness for a chosen job role, and explore how hypothetical improvements change the model's estimate.

Technologies used

Python, Flask (with Jinja templates), HTML, CSS, scikit-learn (Logistic Regression), SQLite, plus NumPy and joblib for data handling and saving the model.

How the prediction workflow operates

  1. You submit the profile form; the server validates every field.
  2. Skills text is matched against a fixed skill catalogue; the number of recognised skills becomes a feature.
  3. The saved pipeline (scaler + classifier, trained by train_model.py) predicts the class and the probability of "Placed".
  4. The result is saved to a local SQLite database and displayed.
  5. Role readiness compares your skills with a role checklist; the What-If Simulator re-runs the same model on edited values without changing your saved record.

Dataset and model evaluation

The training data is synthetic (computer-generated by generate_sample_data.py). It is not real student placement data. The relationships in it were written by the project author, so the model mainly learns those assumptions.

Limitations

  • Synthetic data: results do not represent real placement outcomes.
  • Only seven numeric inputs are used; interviews, communication and company needs are not modelled.
  • Skills are reduced to a count of recognised catalogue skills, so which skill you have does not affect the model.
  • Role checklists are illustrative, not universal hiring requirements.
  • The skill-match percentage is a simple checklist count, not a validated employability score.
  • The model can respond to changes in ways that real recruiters would not.
